COBRANÇA ASAAS (PRODUÇÃO) — PRONTO
  - O Supabase bloqueou a gravação de "Edge Function Secrets" pelo
    conector ("Storing keys is paused"). Para não depender disso, as
    chaves foram guardadas no VAULT do banco (cofre criptografado do
    Supabase) e as Edge Functions passaram a ler de lá:
        asaas_api_key        -> chave de produção que você enviou
        asaas_env            -> production
        asaas_webhook_token  -> token novo (64 caracteres aleatórios)
  - O sistema reconhece sozinho que a chave é de produção ($aact_prod_).
  - Webhook no Asaas: o antigo tinha um token desconhecido; foi apagado
    e recriado ("LojaCerta producao"), mesma URL, mesmos eventos, com o
    token novo. Testado: token errado = recusado (401); certo = aceito.
  - Fluxo completo: cliente clica "Assinar" -> escolhe Pix/cartão/boleto
    -> vai para a fatura do Asaas -> paga -> Asaas avisa o sistema ->
    plano liberado automaticamente com data de vencimento -> recibo por
    e-mail. Fatura vencida = 3 dias de carência; estorno = modo leitura.
  - Exigência do Asaas: a loja precisa ter CNPJ ou CPF preenchido em
    Configurações -> Loja antes de assinar (o app avisa).

           select vault.create_secret('LojaCerta <nao-responda@SEUDOMINIO.com.br>', 'email_from');

TESTE REAL DE PONTA A PONTA (15 min, R$ 59 que voltam)
  1. Crie uma loja de teste (outro e-mail), preencha CPF/CNPJ em
     Configurações -> Loja.
  2. Assinatura -> Essencial mensal -> Pix -> pague o QR Code.
  3. Em até 1 min o plano deve aparecer ativo, com data de vencimento.
  4. No painel do Asaas, estorne esse pagamento (a loja de teste vai
     para modo leitura — é o comportamento certo).
  Para acompanhar no Supabase -> SQL Editor:
     select tipo, processed_at from webhook_events order by processed_at desc limit 10;

TROCAR A CHAVE DO ASAAS DEPOIS DO LANÇAMENTO (boa prática)
  A chave de produção circulou em conversa. Quando der (pode ser na
  semana), gere uma nova no Asaas (Integrações -> Chave de API) e troque
  no Supabase -> SQL Editor (não precisa mexer em código nem deploy):
     select vault.update_secret(
       (select id from vault.secrets where name = 'asaas_api_key'),
       'COLE_A_CHAVE_NOVA_AQUI');
  O sistema passa a usar a nova em até 5 minutos.

SEGREDOS QUE NÃO CONSEGUI CONFERIR (o conector não lista)
  Confirme no Supabase -> Edge Functions -> Secrets que existem:
    - DEV_PIN (12+ caracteres) — PIN da equipe para ativar/suspender
      planos manualmente. Se não existir, a ativação manual funciona só
      com login dev (menos seguro, mas funciona).
    - PURGE_SECRET — mesmo valor do GitHub -> Settings -> Secrets ->
      Actions -> PURGE_SECRET. Usado pela exclusão LGPD automática.
  E no GitHub -> Settings -> Secrets -> Actions:
    - SMOKE_TEST_EMAIL / SMOKE_TEST_PASSWORD (usuário comum de uma loja
      de teste) — sem eles o teste de deploy só roda a parte anônima.
